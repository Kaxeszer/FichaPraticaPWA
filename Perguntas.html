Perguntas:

  1. O que são operações de “Commit”, “Push” e “Pop” efetuadas num repositório?
  2. Quais sáo as vantagens de usar Branchs num repositório git?
  3. Nos Merges de conteúdos resultantes de um “Pop” podem resultar em conflitos. Em que consistem e como podem ser resolvidos esses conflitos?
  4. “Clone” e “Fork” são formas diferentes de replicar um repositório Git. Quais as diferenças entre eles?

Resposta à Pergunta 1:

O Commit é uma operação que regista um conjunto de alterações no histórico do repositório Git local, permitindo acompanhar a evolução do projeto e consultar versões anteriores.

O Push permite enviar os commits e respetivas alterações do repositório local para um repositório remoto, como o GitHub, atualizando-o e facilitando a partilha do trabalho.

O Pop, no contexto do comando git stash pop, permite recuperar e reaplicar alterações que foram guardadas temporariamente através do git stash. Quando a operação é concluída com sucesso, essas alterações são removidas da lista de alterações temporariamente guardadas.

Resposta à Pergunta 2:

As branches permitem criar linhas de desenvolvimento independentes dentro de um repositório Git, possibilitando trabalhar em novas funcionalidades, corrigir erros ou experimentar alterações sem interferir diretamente com a branch principal do projeto.

Entre as principais vantagens destacam-se:

  • A possibilidade de desenvolver diferentes funcionalidades em paralelo;
  • O isolamento das alterações;
  • A organização do trabalho;
  • A facilidade de colaboração entre programadores.

Depois de concluídas e validadas, as alterações podem ser integradas noutra branch através de uma operação de merge.

Resposta à Pergunta 3:

Os conflitos ocorrem quando o Git não consegue integrar automaticamente alterações realizadas sobre o mesmo conteúdo. No contexto do comando git stash pop, isto pode acontecer quando as alterações temporariamente guardadas entram em conflito com as alterações existentes na área de trabalho.

Para resolver estes conflitos, é necessário identificar os ficheiros afetados, analisar as diferenças assinaladas pelo Git e editar o conteúdo para escolher ou combinar as alterações pretendidas. Depois de resolvidos os conflitos, os ficheiros devem ser guardados e adicionados à área de preparação (staging area) através do comando git add. Se o conflito tiver ocorrido durante um merge, a operação poderá ser concluída com um commit.

Resposta à Pergunta 4:

O Clone consiste em criar uma cópia local de um repositório Git existente, incluindo os ficheiros e o histórico de commits. Esta operação permite trabalhar no projeto no computador e sincronizar as alterações com o repositório remoto, desde que existam as permissões necessárias.

O Fork consiste em criar uma cópia de um repositório remoto para a própria conta numa plataforma como o GitHub. Esta cópia permite desenvolver alterações de forma independente, sem modificar diretamente o repositório original.

A principal diferença é que o Clone cria uma cópia local do repositório, enquanto o Fork cria uma cópia remota independente. É comum realizar um Fork e, posteriormente, um Clone dessa cópia para trabalhar localmente. As alterações podem depois ser propostas ao projeto original através de um Pull Request.
